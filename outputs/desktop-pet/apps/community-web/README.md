# desktop pet 共创网站

独立网站，广场浏览、下载与共创均在浏览器进行。控制中心只管理已安装内容和本机配置，并提供本站入口。`dist/` 是可直接托管的静态网站源与产物，不依赖桌面 IPC，不读取用户档案。

首页标题为「共创平台」。顶部导航为「桌宠广场」「需求广场」「插件广场」「共创平台」「安装指南」；首页的「榜单」进入原 `#rankings` 页面，「查看全部」进入原 `#collections` 页面，合集详情和榜单作品仍沿用既有预览、下载与分享流程。制作工作台及原 `#create` 路由保持可用。

## 已实现

- 桌宠广场按 Codex Pet 的白绿布局重做：全宽搜索、分类计数、宽屏四列卡片、作者与简介、查看／安装／分享。保留用户选定的 D 图标，默认浅色，提供明暗主题与手机布局。
- 新公共目录117只桌宠覆盖11类，V1 64只、V2 53只；每只提供九组动作预览、背景切换和完整ZIP，V2另提供十六向注视。卡片和详情仅显示作者，原来源、投稿条款和许可资料保留在作品包中，不使用用户私有安装文件。
- 随机发现、名称／下载／点赞／近七日趋势排序，搜索名称、作者和标签，18 件分批加载与空结果状态；按 `/` 聚焦搜索。
- 互动服务可用时读取全站实际赞与下载；无需账号的匿名互动与投稿能力分开判断，赞、关注与每日下载去重由服务确认。HEAD、封面、预览与失败不计下载。无公共 API 的本机预览继续使用明确标注的浏览器记录，不上传本机历史冒作共享热度。
- 首页展示本站真实作品／类别计数、按收录作品数统计的作者简榜，以及宠物排行、需求和合集入口。作者链接进入本站创作者页，不把署名当作已验证账号。
- 完整社区排行榜采用浅色大标题、真实统计快照、左侧作品／贡献者／系列与右侧本周／总榜，桌宠与插件可独立切换。长行展示编号、作品拼图或封面、作者标识和本站作品数。贡献者行本周三列为近7日下载／近7日点赞／关注者，总榜为累计下载／点赞／关注者；周明细和关注者仅取服务真实分别计数，缺字段为“—”。作品和系列沿用互动／下载／点赞。贡献者与系列以所含作品的真实互动排序，零互动时按本站收录数排序；作品零活动保持空榜。
- `#contributors/pets/{作者名编码}` 和 `#contributors/plugins/{作者名编码}` 展示该署名的实际作品，跨类型切换、关注者、下载及点赞使用本站数据。仅原资料明确提供的主页或用户确认的 Lykinzlj 主页显示外链，未知主页不猜。下载不称为安装成功；统计或关注接口不可用显示“—”，关注灰色。关注经同源 GET／PUT 服务回执更新，不乐观加数、不要求网站密码。
- `#collections` 只展示本站实际作品，支持轮播、搜索、类型筛选、合集详情、逐件动作预览与 ZIP 下载；复制的本机合集链接仅在这台电脑可访问。
- `#requests` 保留四个本站提案示例、本浏览器草稿与导出；“发布制作需求”先保存草稿，再打开本站自有 GitHub 仓库的需求 Issue。用户手动提交后待维护者处理收录，不自动添加公共条目。需求支持／关注仍为浏览器偏好，最多保存 100 件本机草稿。导出生成 Markdown，不把文本生成或下载入口当作已保存文件。
- 安装菜单提供 ZIP、给任意 AI 的安装说明和安装指南；分享菜单可复制作品链接；原始来源入口已移除，必要署名与许可保留在作品包中。本机预览链接只在这台电脑访问，其他电脑请分享作品 ZIP。
- 三个可运行声明式提醒模板的固定 ZIP 下载、重新共创。
- 两个默认不安装的可选工具：文件助手和电脑守护。卡片独立展示功能、权限与本机安装用法，提供实际 SDK V3 JavaScript ZIP；工具由匹配版本 desktop pet 宿主支持，不当作提醒模板编辑。
- 插件广场共 24 件：三个声明式提醒模板，以及仓库全部 21 个真实源码插件。源码包括 14 个官方目录插件和 7 个社区目录插件，覆盖当前本机已安装的 10 件。19 个独立 SDK 插件与两个宿主工具均可下载真实 ZIP、查看权限与配置条件；已安装实例的启停、权限、授权和配置继续在本机管理。
- 源码插件页面显示维护者 `Lykinzlj`。包内 `SHARE.md` 分别记录原作者、维护者与来源，`LICENSE` 保留源目录或仓库的原始全文，不把维护署名冒称上游创作署名。额度伙伴需另行运行本机额度监控程序，Higgsfield 需要用户令牌，Spotify 需要应用 ID 与账号授权，词汇助手的 Anki 保存需要 AnkiConnect；网站不代配或启动这些依赖。
- 本项目的五件插件统一署名为用户确认的 GitHub 用户名 `Lykinzlj`，由 `catalog.js` 的 `projectAuthor` 提供，广场与固定下载包使用同一作者。广场提醒模板保留此署名，自行上传作品的作者由用户填写。上游桌宠保留各自作者、来源与许可；安装指南仅展示安装和 AI 配置步骤，素材说明仍在作品详情与分享包中。
- 共创采用四个独立路由：`#create/pet-make`、`#create/plugin-make`、`#create/pet-import`、`#create/plugin-import`，分别制作桌宠、制作插件、导入桌宠、导入插件。`#create` 仍可进入入口选择，切换保留各自字段与文件。
- 制作桌宠保留 V1/V2 WebP 图集，也可逐动作导入 MP4、WebM、动画 WebP，自定义动作 ID、名称、种类及 AI / 交互状态绑定；缺失状态回退待机。绑定是配置映射；“预览此绑定”在右侧播放对应素材，不执行真实 AI 或交互。
- 已有桌宠与插件支持 ZIP、完整文件夹、清单与配套文件三种上传，只补作品信息，不重绘或修改原包。UTF-8 ZIP 支持 store / deflate，单文件 100 MB、总量 200 MB、最多 1000 文件。
- 插件自行开发后上传，制作入口要求本系统 SDK 1/2/3 与附件齐全；其他宿主和不完整项目用导入入口保留原格式归档。静态检查展示原生兼容、部分支持、需原宿主、无法识别或直接兼容，明确未实际运行。Raycast、Live2D、VPet 按原项目说明在原宿主使用；Shimeji 默认保留原逻辑，仅明确选择后才可在本机创建素材转换副本。网页不执行任何上传代码，不强制改写清单或状态映射。
- 插件可上传 PNG／JPEG／WebP 卡片封面（最大 10 MB），实际解码后以真实卡片布局预览；封面不是运行皮肤。图片进入分享 ZIP，WORK-INFO[-N].json 的 presentation.cover 保存相对路径，再次导入和草稿恢复保留。目录作品声明 cover／presentation.cover 后沿用同一广场卡片展示。
- IndexedDB 保存完整作品文件与信息、封面和动作草稿。四入口分别保存，旧 pet／plugin 草稿可只读恢复后另存新键，原记录不覆盖。分享 ZIP 原样保留目录、未知字段、许可和附属文件，另增 WORK-INFO.json 与分享说明。桌宠与插件四入口均支持“打包并发布”，先检查会话再构建 ZIP，服务确认前不显示发布成功；本机无服务时保留草稿和下载。
- 响应布局、键盘标签操作、减少动态效果、浏览器 WebMCP 广场筛选。

运行包保持现有桌面格式。宠物 ZIP 根目录包含 `pet.json`、`spritesheet.webp`、`SHARE.md`；提醒 ZIP 包含 `openpets.plugin.json`、`SHARE.md`，可选工具 ZIP 另含实际 `index.js`。插件下载后解压并从本地导入文件夹，确认权限及启用。署名说明不会被现有安装器持久保留，接收者需保存原分享包。

文件助手请求 `files/status`，提供文件定位、虚拟分类库、可撤销推荐整理和用户已配置 AI 的分类审核；电脑守护请求 `files/system:metrics/status`，提供资源建议、下载风险提醒、EXE/MSI 只读检查与卸载目录核对，不自动卸载或删除。两者不随桌面捆绑或默认安装，监测另外由用户主动开启。源码在 `plugins/community/lingyin-file-assistant` 与 `lingyin-computer-care`；入口只设置插件状态，实际工具与权限由匹配版本宿主提供，不是任意宿主都能独立执行的程序。网页不接触本机 IPC 或私人资料。

## 验证与更新下载包

从项目根目录运行：

```powershell
node apps/community-web/build-native-contract.mjs
node apps/community-web/build-packages.mjs
node apps/community-web/test-packages.mjs
node --test apps/community-web/tests/*.test.mjs
```

制作与导入使用不同出口规则：制作包复用桌面原纯清单校验器，检查 SDK、权限、入口、动作及映射，浏览器还实际解码需要的图片和动画；导入只补充作品信息并保留原件。来源输入隐藏、可空，作者与许可保留。插件卡片、详情与榜单共用封面。制作插件须符合 64 KiB 清单、1 MiB 入口、5 MiB 单文件和 32 MiB 总量上限，制作出口不会把其他宿主或缺附件的归档误作原生包。`tests/creation-export.test.mjs` 用真实桌面加载器与解码器验收临时制作包，不执行上传代码、不操作用户档案。

包生成器与网站共用 `dist/catalog.js` 和 `dist/package-core.js`，并从明确的仓库插件目录生成 `dist/plugin-catalog.js`，避免广场与下载包漂移。`source-plugin-packages.mjs` 只复制清单、入口、声明素材／面板／翻译和版权说明，不扫描用户档案或混入目录额外的配置、存档。测试用桌面已有 ZIP 解析器、安装器和目录加载器验证真实包、全部源码目录覆盖、SHA-256 与许可；另用带私有额外文件的夹具验证包边界。安装验收在临时档案进行，不安装到用户现有桌宠。

逐动作制作与桌面共用 mediaVersion:1、顶层 actions、actionDefinitions 和 stateBindings 契约。视频预览使用本地 blob，不访问本机 IPC，也不扩大公开文件服务。MP4 需纯色去背；透明 WebM / WebP 可声明 alpha。直接导入不要求重新填动作配置，未知宿主包不会伪装为运行兼容。

社区核心测试保护需求字段校验、损坏记录恢复、支持／关注的有效引用、真实互动排行和现有作品合集，不依赖 DOM 或网络。

`community-data.js` 保存本站提案示例与合集定义，`community-core.js` 校验需求、恢复记录、计算作者榜和排行、解析合集成员，`community-pages.js` 负责社区页面、需求草稿与公共需求适配。`publication-client.js` 校验服务响应，拥有会话、公共作品／需求、发布、赞与统计请求；它只访问共创站同源接口，不提供本机资料或桌面 IPC。

浏览器互动后备、主题和需求草稿分别使用 `pet-community-gallery-activity-v1`、`pet-community-theme`、`pet-community-requests-v1`。需求键保存 `entries`、`supported`、`following`；保存失败会反馈仅留当前页面，可导出。浏览器记录受同源限制，不保证本机随机端口变化后保留；公共作品与全站统计由服务保存，作用域不混用。

## 当前托管接线

本轮改用 Cloudflare Pages，部署与数据库绑定由站点 owner 持有；下方 Sites 状态是先前历史，不表示当前 Cloudflare 上线结果。客户端以 `/api/session` 的 `interactionsAvailable`、`anonymousInteractions` 判断匿名统计与互动，直接上传公示能力 `available` 与仓库投稿能力 `submissionAvailable` 分开；互动上线不等于匿名包可直接公开发布。

本站自有投稿仓库已实际创建为 [xunguangzlj-cloud/desktop-pet-community](https://github.com/xunguangzlj-cloud/desktop-pet-community)，显示作者仍为 Lykinzlj。四入口“打包并发布”生成完整 ZIP 与 SHA-256，再预填该仓库的 `pet-submission.yml` 或 `plugin-submission.yml`；用户手动附包并提交，维护者审核收录后才在网站公示，不向上游仓库投稿。未打开新页面时保留手动表单链接，文件和草稿仍可保存。GitHub Issue 的 ZIP 附件上限为25 MB，更大包按仓库指南通过 PR 提交，仍保留原包，不切碎素材。本站不要求密码，提交 Issue／PR 使用用户自己的 GitHub 侧身份；网页不会代发 Issue、自动附包、自动合并或将生成 ZIP 称作发布成功。
