# 共创网站与本地配置

共创平台是独立浏览器网站，源位于 `apps/community-web`。桌宠广场按用户要求学习 [Codex Pet 广场](https://codexpet.top/#gallery) 的白绿视觉、卡片排版和浏览功能；控制中心继续使用参考 [鸣潮 WIKI](https://wiki.kurobbs.com/mc/home) 的本地配置界面。作品浏览、桌宠与插件制作、包下载在网站进行；控制中心只保留网站入口、已安装内容、手动导入和本机配置。已选 D 方案品牌图继续用于 desktop pet 网站顶栏和 favicon，不充当动作图集。

## 广场浏览

广场以大标题、作品数、搜索框、分类与计数、排序和卡片网格组织内容，宽屏使用四列，较窄视口减少列数；默认使用用户确认的浅色背景，支持手动切换明暗主题并记忆明确选择的深色偏好，存储不可用时仍使用浅色。卡片展示作品预览、分类、V1/V2 版本、作者和关键词标签。每批展示 18 个结果，点击加载更多继续展示，筛选变化重新从首批开始；空结果明确显示状态。

搜索覆盖作品名称、作者、简介、分类和标签，可用 `/` 快捷键聚焦。排序包含随机、点赞、下载、近七日活动和名称；随机顺序在当前网站会话中建立，一键随机发现从当前筛选结果中打开作品详情。

卡片点赞可再次点击取消。下载菜单提供下载 ZIP、复制给任意 AI 的安装说明和阅读安装指南；分享菜单仅提供复制当前作品链接；所有桌宠的原始来源按钮已移除，许可与必要署名保留在分享包。本机预览链接只能在这台电脑访问，复制时明确提示。浏览器拒绝剪贴板访问时显示失败提示，用户仍可通过安装指南或下载继续。

### 公共统计与本浏览器记录

提供互动服务的网站通过 `/api/activity` 读取实际共享统计，内置117个桌宠、24个插件与新投稿使用同一榜单数据。客户端将 `/api/session` 的 `interactionsAvailable`、`anonymousInteractions` 与投稿的 `available` 分开，不要求账号或网站密码即可使用已接通的匿名互动；点赞、关注与每日下载去重由服务确认。下载只在文件GET成功时记录，HEAD、封面、预览与失败不计。近七日合计互动沿用weekly；贡献者榜周下载／周点赞只读取服务明确的weeklyDownloads／weeklyLikes，缺字段显示“—”，不从合计拆分。零记录保持空作品榜，统计不证明文件已保存或作品已安装。

本机无公共 API 时继续使用 `pet-community-gallery-activity-v1` 中的浏览器记录，并明确其作用域；接通公共服务后不将本机历史上传为全站热度。`pet-community-theme` 保存主题偏好。两键受同源限制，本机随机端口变化后不保证跨启动保留。

## 首页与社区页面

首页主标题为“共创平台”，保留作品和分类统计。顶部展示“桌宠广场”“需求广场”“插件广场”“共创平台”“安装指南”；首页不再展示“浏览并安装”“申请喜欢的角色”按钮及“逐件署名”统计卡。合集和榜单仍保留完整页面与原 hash 路由，分别从首页“查看全部”和“榜单”入口进入。作品预览、下载、共创工作台和单件素材声明沿用原行为。

首页模块和`#rankings`、`#requests`、`#collections`、`#contributors`是同一静态网站的客户端页面，不新增桌面操作接口。新公共目录收录117件、11类别；作品与类别数量从本站目录计算，不把官网316归档总数冒充本站收录数。首页创作者简榜按原作者声明统计本站收录量，署名不等于已验证账号；点击作者打开本站创作者作品页。

宠物与插件排行采用同一统计作用域，可查看近七日活动或累计互动。完整页保持浅色，标题“社区排行榜”旁展示本次真实读取快照与刷新条件，作品／贡献者／系列和本周／总榜分别切换。长行展示排名、作品拼图或插件封面、作者标识／实际作品数、互动和累计下载／点赞。贡献者和系列根据所含作品聚合互动，零互动时按收录量排序；作品没有互动时保持空榜，不用随机顺序冒充热门。宠物系列沿用本站合集；插件系列按实际分类组织。原`rankings/pets`、`plugins`、`authors`、`plugin-authors`、`collections`路由保留，新增`plugin-collections`。

作者页`#contributors/pets/{编码署名}`和`#contributors/plugins/{编码署名}`展示返回榜单、创作者名／@标识／本站贡献数、关注和明确提供的作者主页，以及当前类型的作品、关注者、下载、点赞四项数据与原作品卡片。桌面四指标横排以细边线分隔，与作者按钮同底边；窄屏换行，不用四张独立卡片。作品标题为“作者名 的桌宠／插件”。按exact原作者字段分组，可切换此署名的桌宠与插件；不合并相似名字。仅资料明确声明的HTTPS主页显示外链，用户已确认的Lykinzlj主页由项目署名配置提供。关注接口为`GET/PUT /api/contributors/{编码署名}?kind=pets|plugins`，PUT传`{following:boolean}`；同一作者的关注跨类型共享，收到服务回执才更改数目。贡献者榜使用同一activity快照顶层contributors的真实followers，Map保exact作者，不逐作者发起请求；缺字段显示“—”。缺服务时关注灰色，坏回执或失败不伪造零值或增长；旧异步回执不会写入新选中的作者／类型。

合集只收录本站已有作品，按实际目录显示作品数；目前包括星铁、原神、动物伙伴、动漫伙伴、原创助手和 AI 灵感伙伴。合集支持轮播、搜索和类型筛选，详情逐件提供动作预览和 ZIP 下载，可复制当前合集链接。合集作品沿用广场预览和下载，不为填满版面增加虚构作品；本机合集链接仍只在这台电脑可访问。

需求页包含四个明确标注的本站创作提案示例，用已入库作品的单帧缩略图作为造型参考。它们不是上游实时公共请求，不复制来源待核实的需求参考图，也不预填点赞或关注热度。

需求表单经字段校验后保存本浏览器草稿，生成本地编号与创建时间，最多保存 100 件。`pet-community-requests-v1` 保存草稿 `entries`、支持 `supported` 和关注 `following`；支持和关注均可取消，每件显示本浏览器的 0/1 状态。这个键同样受网站源限制，随机端口变化后不保证保留。持久保存失败时明确反馈仅留在当前页面，并保留导出入口。

需求导出将自己的需求及已支持或关注的提案生成可见Markdown，可复制或下载；生成文本不表示文件已保存。“发布制作需求”先保存本浏览器草稿，再打开本站自有GitHub仓库的普通Issue，预填名称、分类、图集版本和说明。用户手动提交并等待维护者处理收录，不自动添加公共条目；弹窗被拦截仍有手动链接，失败保草稿和导出。需求支持与关注仍是浏览器偏好，不冒作共享赞数，也不与作者关注混同。

## 详情和制作

工作台保留制作桌宠、制作插件、导入桌宠、导入插件四入口，移除长篇操作说明和来源输入展示。作者和许可仍是作品信息；来源可空，旧草稿或原包信息不因此删除，详情不自动展示第三方源码链接，原包许可证和版权文件继续原样保留。插件封面同时用于卡片、详情和排行。

制作导出由 `prepareWorkPackage` 检查，导入归档不受同样的运行限制。浏览器 `native-package-contract.js` 通过 `build-native-contract.mjs` 从桌面原清单所有者生成，复用 SDK／权限／配置／入口、媒体与图集元数据及九加三种状态。插件制作对齐本机 64 KiB 清单、1 MiB 入口和完整包 1 GiB／单文件 512 MiB／10000 文件上限，并继续检查声明素材与面板的各自上限；封面也计入这些运行包上限。桌宠制作检查实际 MP4／WebM 文件头，WebP 动作需 2 至 600 帧、单帧不超过 2048 × 2048，alpha 模式需透明通道，浏览器在导出前实际解码动画各帧；图集与插件 sprite 核对真实格式和尺寸。静态检查不执行 JavaScript 或原宿主逻辑，插件功能仍须创作者自行测试；MP4／WebM 完整播放依赖桌面 Chromium。导出测试实际安装到临时桌面档案，并让桌面原图集与媒体解码器接受生成包；不操作用户原档案。

插件广场统一使用封面或居中图标、点赞与下载计数、名称、分类、作者、简介及操作按钮的卡片布局。卡片与制作预览不显示“本机插件”或技术能力列表，普通详情也不重复此类标签及权限列表；实际导入、安装和启用的权限校验保持不变。

每件作品的详情读取自己的图集、版本、作者声明和下载包，不用同一只桌宠替代预览。网站支持 V1/V2 WebP 图集检查、九组动作预览与兼容 ZIP 制作。详情和制作工作台提供动作按钮与下拉选择；V2 另提供 16 向单帧注视，按从屏幕上方开始、顺时针每档 22.5° 的图集契约预览，V1 不显示方向按钮。两处预览均可切换浅色、深色和透明棋盘背景，便于观察角色与透明边缘。

共创平台有四个独立入口：`#create/pet-make` 制作桌宠、`#create/plugin-make` 制作插件、`#create/pet-import` 导入桌宠、`#create/plugin-import` 导入插件；`#create` 展示入口选择。切换时分别保留当前页面的文件和字段，不把制作表单的数据挪到导入流程。制作使用本系统规范，导入保留原项目格式与逻辑，不强制映射或自动转换。

制作桌宠可继续使用 V1/V2 图集，也可上传 1 至 100 个 MP4、WebM 或动画 WebP 独立动作；用户自定义动作 ID、名称和种类，按需绑定九个 AI 状态及睡觉、点击、拖拽。清单使用 mediaVersion:1、顶层 actions、actionDefinitions、stateBindings，缺失状态回退待机；不为补齐动作复制同一个文件。绑定下拉框配置状态与动作的对应关系，不执行 AI、交互或电脑操作。“预览此绑定”会在右侧切换实际映射素材，并显示状态与动作名称；它只播放素材，不触发真实事件。AI 状态由已接入工具的真实事件提供，点击和拖拽由桌面交互提供，睡觉需对应生活插件或状态；未接入 AI 仍使用本机安静模式或随机动作设置。视频只通过本地 blob 预览，网页不联网生成素材、不扩展本机服务。MP4 选择纯色去背，透明 WebM / WebP 可声明 alpha。“没有图集用任意 AI 辅助制作”入口及其专用文案已移除。

“导入桌宠”接受 ZIP、完整文件夹或清单及配套文件，只需补作品信息，保留原文件及元数据，不要求重新制作图集。ZIP 支持 store / deflate 及单外层目录，文件名使用 UTF-8，单文件 512 MiB、全部 1 GiB、最多 10000 文件；拒绝绝对路径、上级目录、系统保留名、链接和重名冲突。原始许可、未知扩展字段、附属素材全部保留，另加 WORK-INFO.json 和不覆盖原说明的 SHARE 文件。清单位于 release 等子目录时，完整分享仍保留父层 LICENSE / README，不按清单子树裁剪。

制作插件在用户自己的开发工具中按本系统 SDK 完成，再上传 ZIP、文件夹或清单与配套文件，填写作品名称、介绍、署名和许可。识别 desktop-pet.plugin.json、plugin.json、openpets.plugin.json 的 SDK 1／2／3 清单；网页只读取权限与清单，检查入口、assets 声明（包括 sprites.path）、panels 和翻译附件的安全路径及存在性，不执行代码。SDK 使用 $t: 时需提供 locales/en.json 回退翻译并补齐引用键，翻译 JSON 限 256 KiB；缺附件不显示为原生兼容，制作入口要求补齐，导入入口仍可保留原包归档。网页归档、制作打包与本机完整包导入共用 1 GiB／单文件 512 MiB／10000 文件边界，执行入口和声明资源的较小安全限额继续保留。插件发布以服务确认结果为准；未提供发布服务的本机页面保留草稿和下载。

插件图片只作为广场卡片封面，不改变运行界面、皮肤或面板。支持 10 MiB 以内的 PNG、JPEG、WebP，检查文件签名后用浏览器实际解码，失败会反馈；右侧复用真实广场卡片布局预览。图片 bytes 保留到分享包的 `community-cover/`，新增作品信息 `WORK-INFO[-N].json` 的 `presentation.cover` 指向该相对文件。重复导入读取编号最新的作品信息和封面，原插件清单、原代码、原许可均不覆盖；移除本次封面不删除历史原图文件。公开目录作品可声明 cover／presentation.cover 作为卡片图，没有封面时沿用图标。封面展示不代表公共投稿成功。

导入页先显示“静态兼容性检查”，区分原生兼容、部分支持、需原宿主、无法识别或直接兼容；报告含 `inspection: static`、格式、能力开关、支持范围、不支持范围和原因。只检查文件与已知清单结构，不进行实际运行测试。原生桌宠可以预览原包待机素材，动作与绑定沿用原清单；网页不改写导入映射。Shimeji 的图像帧可另建转换副本，但原 Java／条件行为仍需专用引擎；默认只保留原包，不自动转换。Raycast、Live2D、VPet 等需原宿主；无法识别格式也可归档下载，运行、配置、动作及 AI 绑定按钮灰色并解释按原项目说明使用。多个作品目录不会自动选第一个假报兼容，需单独选择运行作品。所有原包文件和原逻辑保留并不表示本系统已经执行或实现原逻辑。

制作草稿由 IndexedDB 的 desktop-pet-creator-drafts / works 保存完整文件、作品信息、封面、动作和绑定。四入口使用 pet-make、plugin-make、pet-import、plugin-import 四个独立键；恢复不要求重新上传。当前入口无新草稿时只读旧 pet／plugin 草稿，旧记录保留，之后保存写入当前新键，不覆盖旧草稿。保存失败明确提示下载保留。草稿受同源及浏览器空间限制，清理网站数据会删除；随机端口不保证跨启动可恢复。

插件支持完整自主开发作品上传、清单权限预览与原包ZIP导出。新桌宠公共目录117件（V1 64、V2 53），保留原图集、清单和投稿文件，按明确素材再分发条款筛选；其余199原件只归档。插件保留三个可用提醒模板。卡片和桌宠详情只显示作者，原来源及素材许可链在包内保留，不标为本项目原创，不虚构社区用户或全站数据。`build-packages.mjs`原样打包上游三原件，`test-packages.mjs`使用真实桌面完整读取器和图像解码器核对新包及400公开资源摘要。

### 可选工具插件

两个工具的下载路径是`/assets/lingyin.file-assistant.zip`和`/assets/lingyin.computer-care.zip`，与其他插件固定路径一起登记，不开放插件源目录或任意ZIP。包测试读取真实清单与入口，使用桌面安装器／目录加载器安装到临时档案，并以SDK测试宿主验证状态启动和权限拒绝。117桌宠与三个提醒模板的兼容验证保持有效。
