# Windows 电脑诊断

`companion-diagnostics.ts` 负责本地只读采集；主进程可以调用
`collectCompanionDiagnostics()` 取得证据快照，调用
`captureCompanionWindowUnderCursor(3)` 给用户三秒把鼠标移到待调查窗口。
共享类型位于 `companion-diagnostics-types.ts`。界面只使用经过协议校验的结果，
不取得任意 shell 执行能力。

用户界面与 AI 诊断入口只在可选“电脑守护” (`lingyin.computer-care`) 已安装启用、具备已批准的 `files` 和 `system:metrics` 权限且实际运行时开放。工具从共创网站下载，不捆绑或自动安装；在本地插件管理中配置。停用或运行损坏取消当前采集和诊断分析、撤销 AI 预览并暂停后台监测，保留原设置和证据存档。使用流程见[可选电脑与文件工具](/companion-tools)。

## 实际覆盖

| 内容 | 证据及限制 |
| --- | --- |
| 磁盘 | 本机固定磁盘的总量和可用量；没有递归扫描文件，也不能判断哪些内容可删。 |
| 内存 | 系统物理内存和进程工作集；共享页意味着工作集不能简单相加。 |
| CPU | 约一秒的前后采样，进程 CPU 按逻辑处理器数归一化；核对进程创建时间，防止 PID 复用。 |
| 自启 | HKCU/HKLM、适用 32/64 位视图的 Run 和 RunOnce，加当前用户和公共启动文件夹；不含服务、计划任务等。 |
| 软件 | 卸载注册表中的名称、版本、发布者和原登记安装目录；不承诺覆盖所有商店应用及便携软件，不查询 Win32_Product。 |
| 窗口 | 当前桌面的可见且非最小化顶层窗口，记录标题、句柄、PID、进程名及可查询的映像路径；指认取鼠标位置的根窗口。 |

软件条目的 `id` 保留注册表 hive、视图和 key。`installedAppsComplete`
只有全部适用注册表视图成功、未达到条数上限时才为真；若为假，软件比较功能
不能据此宣布某个旧条目已被移除。即使为真，也只是登记软件清单完整，
不代表全部安装渠道。`InstallDate` 不用作准确首次安装时间。

窗口归属是调查起点。系统 Toast 可能由宿主进程承载；浏览器广告通常只能
定位到浏览器，不能自动识别网站或通知发布应用。进程名、窗口位置和较高资源
占用都不能独立证明是广告、捆绑或恶意软件。权限不足或进程退出时路径及 CPU
测量保留为空。

## 生命周期与边界

固定脚本位于 `apps/desktop/assets/companion/windows-diagnostics.ps1`，使用
参数数组和隐藏的 Windows PowerShell 子进程，不把任何采集内容拼成命令。
每次最多运行 30 秒，输出最多 4 MiB。返回最多 500 个进程（按工作集排序）、
400 个可见窗口、1000 个软件条目、1000 个自启条目；截断和部分读取失败
保留在 `collectionIssues`。同类并发请求共享当前一次采集；应用退出由
`cancelCompanionDiagnostics()` 终止尚未完成的采集。

打包时必须把 `assets/companion/**` 放进 `asarUnpack`；采集器不从 ASAR
内部直接交给 PowerShell 执行。脚本采用 UTF-8 BOM，保证 Windows PowerShell
5.1 能正确读取中文。

采集没有网络请求、不执行登记的启动命令、不请求管理员权限、不结束进程，
也不修改文件、注册表、自启和安装状态。窗口标题、路径和命令只供本地显示；
不能随诊断自动发送给 AI。

`findings` 只给出稳定 ID 和复查线索，覆盖磁盘剩余不足 10%、本次内存或 CPU
达到 85% 的情况。单次 CPU 峰值并不证明持续卡顿。忽略、后台监测频率、
连续异常判断和发送前预览由界面及其状态所有者负责；本模块没有 AI 执行器。

## 验证

电脑体检界面由 `renderer/src/companion/CompanionDiagnosticsView.tsx` 使用
`CompanionToolsApi` 调用主进程服务。首次打开不自动采集；用户可以开始检查、
开启后台监测、将发现延后一小时或长期忽略，之后恢复提醒。界面保留检查时间、
短采样时长及读取问题，不把短期峰值或窗口进程归属包装为已确定的故障来源。
进程前 20 个、登记软件、自启和可见窗口采用折叠清单；系统设置只使用固定
存储、启动应用和已安装应用入口。操作期间显示忙碌状态，错误直接呈现。

`tests/companion-diagnostics.test.ts` 保护受限数据不被替换成零、软件清单完整性、
发现 ID、无效及超大协议数据的拒绝、窗口归属能力范围。实际 Windows 采集应
另外验证磁盘、进程、登记软件和窗口字段，不把沙箱内的空窗口列表当作桌面
来源已经识别成功。
